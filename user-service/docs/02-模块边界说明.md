| 缓存 / 异常 / 日志治理 | 四类 Redis key 失效、UserGrpcStatusMapper、SensitiveLogUtil |

## Swagger 适配边界说明

1. **Swagger 文档描述的是 gateway REST**，不是 user-service 对外 API。
2. user-service 新增 gRPC 是为 gateway **编排调用**提供事实数据与写能力。
3. **LoginResultVO 中的 accessToken / refreshToken 由 gateway 生成**，user-service 只返回 user_id、pending、token_version 等。
4. **Presign 返回的 URL 由 ObjectStorageService 生成**（dev 可 mock），gateway 转发给客户端。
5. **HomeCard 只返回 target 用户资料快照**，不校验是否 match、不记 visit。

---

## 下游接入原则

1. 只通过 **gRPC** 调用 user-service，禁止直连 `user_center`。
2. 展示头像用 `avatar_key` / AvatarVO，URL 由 gateway/CDN 拼接。
3. 外显头像以批量接口返回为准（仅 APPROVED）；本人中心用 GetSelfProfile / GetUserProfileView。
4. 用户是否可用先调 `CheckUserAvailable` 或读批量结果中的 `available`。
5. 封禁用户：`USER_BANNED` / `available=false`，由下游拒绝互动。

## 技术边界

- Mapper：单表，无 JOIN
- Manager：单表封装，无跨 Manager 编排
- Service：业务编排与聚合
- gRPC：入参/出参转换 + 异常抛出
- Entity：不直接作为 gRPC 响应
