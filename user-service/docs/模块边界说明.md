# user-service 模块边界说明

---

## user-service 负责

| 能力 | 说明 |
|---|---|
| 用户注册 | BH 用户四表初始化，BCrypt，identity 幂等 |
| 用户登录校验 | 密码与账号状态，更新设备与登录时间 |
| 用户主表状态 | account_status、profile_status、token_version |
| 用户资料 | 查询/更新、完整度评分 |
| 头像 / 相册 object key | 绑定 key、列表查询，不上传文件 |
| 设备记录 | 登录 upsert user_devices |
| 用户设置初始记录 | 注册写 user_settings 默认值 |
| 批量资料查询 | basic / recommend 快照，只读 |
| 用户可用性判断 | CheckUserAvailable，供下游过滤 |
| 缓存与异常治理 | Redis cache-aside、统一 gRPC 映射、日志脱敏 |

---

## user-service 不负责

| 能力 | 应由谁做 |
|---|---|
| JWT 签发 / 刷新 | mobile-gateway |
| gateway REST 用户 API | mobile-gateway |
| 短信 / 邮箱验证码 | 独立验证服务或 gateway 编排 |
| OAuth / 第三方登录 | 后续 auth 扩展或 gateway |
| 推荐算法 / 匹配排序 | match-service |
| AI 用户画像 | ai-chat / 后续阶段 |
| IM 消息 / OpenIM 注册 | im-service |
| 图片上传 / 存储 | 客户端 + MinIO；user-service 只存 key |
| MinIO presigned URL | gateway 或独立媒体服务 |
| 图片审核通过 | 后续审核服务；当前默认 PENDING |
| 支付账户 | payment-service |
| Feed / Post 业务 | post-service |
| 跨服务事务 | 各服务本地事务 + 最终一致 |
| 直连其他服务数据库 | 禁止 |

---

## 下游接入原则

1. 只通过 **gRPC** 调用 user-service，禁止直连 `user_center`。
2. 展示头像用 `avatar_key`，URL 由 gateway/CDN 拼接。
3. 外显头像以批量接口返回为准（仅 APPROVED）；本人中心用 GetSelfProfile。
4. 用户是否可用先调 `CheckUserAvailable` 或读批量结果中的 `available`。
5. 封禁用户：`USER_BANNED` / `available=false`，由下游拒绝互动。

## 技术边界

- Mapper：单表，无 JOIN
- Manager：单表封装，无跨 Manager 编排
- Service：业务编排与聚合
- gRPC：入参/出参转换 + 异常抛出
- Entity：不直接作为 gRPC 响应
