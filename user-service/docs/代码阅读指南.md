# user-service 代码阅读指南

按推荐顺序阅读，每轮建立一层认知，避免一上来扎进 Mapper。

---

## 第一轮：看接口（契约）

| 文件 | 关注点 |
|---|---|
| `proto/user/user_auth_service.proto` | Register、VerifyLogin 入参出参 |
| `proto/user/user_profile_service.proto` | 资料、照片、批量、可用性 7 个 RPC |

先弄清：**对外承诺什么**，再回头看 Java 是否兑现。

---

## 第二轮：看入口（gRPC 薄层）

| 类 | 路径 |
|---|---|
| `UserAuthGrpcService` | `grpc/UserAuthGrpcService.java` |
| `UserProfileGrpcService` | `grpc/UserProfileGrpcService.java` |

关注：是否只做 convert + delegate；异常是否交给 Advice。

---

## 第三轮：看核心业务（Service）

| 类 | 职责 |
|---|---|
| `UserAuthServiceImpl` | 注册四表、登录校验、设备 upsert |
| `UserProfileServiceImpl` | GetSelf / UpdateProfile、缓存失效 |
| `UserPhotoServiceImpl` | BindUserPhoto、ListUserPhotos |
| `UserProfileQueryServiceImpl` | 三个批量读 + cache-aside |

阅读顺序建议：Register → VerifyLogin → UpdateProfile → BindUserPhoto → BatchGetBasicProfiles。

---

## 第四轮：看支撑能力

| 类 | 作用 |
|---|---|
| `IdentityHashService` | 手机号/邮箱归一化 + SHA-256 |
| `PasswordHashService` | BCrypt |
| `ProfileCompletionCalculator` | profile_score / completed |
| `ProfileStatusResolver` | profile_status 状态推进 |
| `PhotoObjectKeyValidator` | object_key 格式与归属前缀 |
| `UserProfileCacheServiceImpl` | Redis get/set/delete + 降级 |
| `UserGrpcStatusMapper` | errorCode → Status |
| `SlowCallLogger` | 慢调用 warn |

---

## 阅读技巧

1. 跟一条 RPC 从 Grpc → Service → Manager → Mapper XML。
2. 批量查询同时打开 `UserProfileCacheServiceImpl` 看 cache-aside。
3. 改资料/绑图时跟 `UserCacheInvalidationService` 看删哪些 key。
4. 遇 `UserBizException` 查 `UserErrorCode` 枚举与 `UserGrpcStatusMapper`。
