# PostService 数据模型

Schema：`post_center`（Flyway 管理，历史表 `flyway_history_post`）

## 表一览

| 表名 | 迁移 | 作用 |
|------|------|------|
| posts | V001 | 帖子主表 |
| post_images | V001 | 帖子图片（MinIO key） |
| post_stats | V001 | 点赞/评论 DB 基准计数 |
| post_likes | V002 | 点赞幂等 |
| post_comments | V002 | 评论 |

---

## posts

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 物理自增 PK，不对外 |
| post_id | BIGINT UNIQUE | **业务主键**，对外 postId |
| user_id | BIGINT | 作者 userId |
| content | VARCHAR(1024) | 正文 |
| status | SMALLINT | 1=正常，0=下线 |
| deleted | SMALLINT | 0=未删，1=逻辑删 |
| created_at / updated_at | TIMESTAMPTZ | UTC |

**索引：**

- `idx_posts_user_created (user_id, created_at DESC)` — 用户列表
- `idx_posts_post_id_active (post_id) WHERE deleted=0` — 活跃帖查询

---

## post_images

| 字段 | 类型 | 说明 |
|------|------|------|
| post_id | BIGINT | 所属帖子 |
| sort_order | SMALLINT | 排序 0～8 |
| image_key | VARCHAR(256) | MinIO object key |
| created_at | TIMESTAMPTZ | — |

**主键：** `(post_id, sort_order)`  
**约束：** 最多 9 张（Service 层校验）

---

## post_stats

| 字段 | 类型 | 说明 |
|------|------|------|
| post_id | BIGINT PK | 与 posts.post_id 对应 |
| like_count | INT | 点赞 DB 基准值 |
| comment_count | INT | 评论 DB 基准值 |
| updated_at | TIMESTAMPTZ | 刷盘更新时间 |

发帖时 `insertInitial` 置 0；增量由 Job 从 Redis delta 合并。

---

## post_likes

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | BIGINT | 点赞用户 |
| post_id | BIGINT | 被点赞帖 |
| status | SMALLINT | 1=LIKE，0=UNLIKE |
| created_at / updated_at | TIMESTAMPTZ | — |

**主键：** `(user_id, post_id)` — 幂等核心  
**索引：** `idx_post_likes_post_id`

---

## post_comments

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 物理 PK |
| comment_id | BIGINT UNIQUE | **业务主键** |
| post_id | BIGINT | 所属帖 |
| user_id | BIGINT | 评论作者 |
| root_id | BIGINT | 根评论，一级=0 |
| parent_id | BIGINT | 父评论，一级=0 |
| reply_to_user_id | BIGINT | 被回复用户，一级=0 |
| content | VARCHAR(512) | 正文 |
| status | SMALLINT | 1=正常，0=删 |
| deleted | SMALLINT | 逻辑删除 |
| created_at / updated_at | TIMESTAMPTZ | — |

**索引：** `idx_post_comments_post_root (post_id, root_id, comment_id DESC)`

---

## 为什么使用业务主键 post_id / comment_id

1. **对外稳定**：API/gRPC 只暴露业务 ID，隐藏 DB 自增 id。
2. **分布式发号**：Snowflake 在 Service 层生成，写入前即确定 ID。
3. **Redis / Feed 友好**：key 与 ZSet member 直接用 postId，无需二次映射。

## 为什么逻辑删除

1. **审计与补偿**：保留 post_images、post_stats、post_likes 历史关联。
2. **互动数据不丢**：删帖不物理删点赞/评论记录（Feed 读时跳过不存在帖）。
3. **MyBatis-Plus `@TableLogic`**：posts 查询自动过滤 deleted=1。

## ER 关系（逻辑，无 FK）

```text
posts (1) ──< post_images
posts (1) ── (1) post_stats
posts (1) ──< post_likes
posts (1) ──< post_comments
```

表间不做外键约束，由 Service/Manager 保证一致性。
