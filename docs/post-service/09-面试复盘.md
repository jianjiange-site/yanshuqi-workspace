# PostService 面试复盘

## 1 分钟项目介绍

> PostService 是我们 Dating App 的 UGC 内容微服务，负责发帖、详情、用户帖列表、点赞评论和推荐 Feed。对外是 gRPC 9 个 RPC，内部 PostgreSQL 存帖子和互动，Redis 做详情缓存、计数增量和 Feed 池。我完成了从 proto 契约到 Feed 三路混排的完整链路，并在无 gateway 阶段用 Debug REST 和一键脚本验收。点赞用联合主键幂等，计数用 Redis delta 加定时刷盘，Feed 混排热门、好友时间线和冷启动三路。

---

## 3 分钟技术架构

1. **入口**：gRPC + dev/test Debug REST，callerUserId 走 Metadata `x-user-id`。
2. **分层**：Grpc → Service → Manager/Repository → Mapper/Redis。
3. **存储**：PG `post_center` 五表；Redis `yanshuqi:` 前缀。
4. **发帖**：事务写三表，事务外写缓存、冷启动池、异步 fanout。
5. **互动**：点赞 upsert 幂等，仅状态变更加 Redis delta。
6. **计数**：读时 DB+delta，Job Lua 刷盘合并写 post_stats。
7. **Feed**：5 分钟重建热门池，读时三路混排 + Set 已读去重。
8. **外部依赖**：UserProfileClient fallback，未接真实 user-service。

## 帖子主链路怎么讲

- Snowflake 生成 postId 作为业务主键
- 事务内 posts + post_images + post_stats 初始 0
- 详情先查 Redis，miss 回 DB 组装
- 删帖逻辑删，保留互动历史，驱逐缓存

**追问：为什么 image 只存 key？**  
MinIO 存对象，服务间传 key；URL 由 gateway 或 CDN 层拼，避免 URL 过期耦合。

---

## 点赞幂等怎么讲

- `(user_id, post_id)` 联合主键，PostgreSQL `ON CONFLICT DO UPDATE`
- Manager 返回是否 status 变化，**只有变化才 INCR Redis**
- 重复点赞返回 success 但不加计数

**追问：取消赞再点赞呢？**  
status 0→1，delta +1，计数正确。

---

## Redis 计数刷盘怎么讲

- 写：INCR delta，不 UPDATE post_stats
- 读：`post_stats + delta`，用户看到实时数
- 刷盘：60s Job，Lua 原子取 delta 归零，批量 UPDATE
- 为何 Lua：防 GET 和 SET0 之间丢 INCR

**追问：Redis 挂了怎么办？**  
写 warn 丢增量，读 delta 当 0，显示 DB 基准；恢复后新互动仍写 delta。

---

## Feed 推荐怎么讲

- 三路：recommend（5min 热度重建）、cold_start（发帖写入）、timeline（好友 fanout，当前 fallback 为空）
- 异性分桶：男看女池
- 混排：第 3 位 timeline，第 6 位 cold_start，其余 recommend
- 已读 Redis Set 去重，cursor `recOffset:csOffset`
- 热门池 tmp + rename 原子切换

**追问：为什么不用 ES？**  
当前阶段轻量 ZSet + 定时打分够用，降低运维复杂度；后续可接 ES 做召回。

## 常见追问 Q&A

| 问题 | 简洁答 |
|------|--------|
| 为什么没做 gateway？ | 分阶段交付，post-service 先独立验收，gateway 后接 JWT+gRPC |
| 如何保证删帖后 Feed 不出现？ | getPostDetail POST_NOT_FOUND，Feed 跳过 |
| 楼中楼呢？ | 表有 root_id/parent_id，业务只做一级评论 |
| 好友 timeline 空的？ | user-service 未接，Fallback 好友列表为空，Feed 降级两路 |
| 分布式事务？ | 不做；DB 事务 + Redis best-effort |
| BloomFilter 为什么没用？ | Set 简单准确，后续可换 Redisson |
| 评论为什么 ZSet 200 条？ | 热数据窗口，老评论回源 DB |
| 热度为何评论权重更高？ | 评论代表更深互动，比纯点赞更能反映质量 |
