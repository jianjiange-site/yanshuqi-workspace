## 入口说明

### gRPC

- 类：`PostGrpcService`（`@Profile("!test")`）
- 拦截器：`GrpcUserContextInterceptor` 从 Metadata 读取 `x-user-id`
- 异常：`PostGrpcExceptionAdvice` + `PostGrpcStatusMapper`

### Debug REST

- 类：`PostDebugController`
- 路径前缀：`/internal/debug/post`
- Profile：`dev` / `test` 才暴露
- 用途：**无 gateway 阶段的本地验收入口**，不是公网正式 API

## 基础设施依赖

| 组件 | 用途 | 失败策略 |
|------|------|----------|
| PostgreSQL | 主存储 | 写失败抛错；读不到 POST_NOT_FOUND |
| Redis | 缓存 / 增量 / Feed | warn + fail-open（读降级 DB） |
| Flyway | V001/V002 建表 | 启动迁移 |
| MyBatis-Plus | ORM + 逻辑删除 | — |
| Nacos / Minio | 健康检查 | 不影响业务单测（MockBean） |

## user-service Fallback

```text
UserProfileClient (接口)
    └── FallbackUserProfileClient (@Component)
            ├── getGenderBucket: userId % 2
            ├── batchGetGenderBuckets: 批量 fallback
            └── getFriendUserIds: 空列表
```

后续替换为 gRPC 实现时，只需新增 Client 实现并调整 Bean 注入，Feed / 写扩散逻辑不变。

## 不依赖 gateway 的验收方式

1. **gRPC**：grpcurl + `-H x-user-id: {uid}`
2. **Debug REST**：Header / query `x-user-id` 或 `callerUserId`
3. **单元测试**：Mockito 测 Service / gRPC 层
4. **一键脚本**：`scripts/verify-post-service.sh|ps1`（不启动 PG/Redis 进程）

## 关键设计约束

- **不做多表 JOIN**：Manager 层分别查 posts / images / stats 再组装
- **DB 是事实源**：Redis 是缓存与写合并层
- **事务边界**：发帖/删帖/点赞 upsert 在 `@Transactional` 内；Redis 在事务外 best-effort
